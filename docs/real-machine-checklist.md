# 真机验证清单

CI 在 Windows Server 虚拟机上跑脚本和往返测试，能发现大部分问题，但下面这些只有在真实的家用电脑上才能确认。写代码时查不到官方依据、或者依赖具体硬件的地方，都记在这里。验证完一项，就在对应的 YAML 或脚本注释里写明结果，然后从这里删掉。

建议的测试机：Win11 家庭中文版（最新两个版本）、Win11 专业版、Win10 22H2 家庭版，至少一台笔记本、一台带机械硬盘的老台式机。

## 检测

| 检测 | 要确认什么 | 怎么验证 |
| --- | --- | --- |
| `system.winre-status`、`system.winre-image` | `ReAgent.xml` 里 `InstallState` 的含义（1 = 开，0 = 关）来自社区工具，微软没有公开这个格式；文件不存在时现在显示「没查出来」；关着的时候映像文件是不是都在 `C:\Windows\System32\Recovery\Winre.wim`（隐藏文件；不在就报 no-image，不给修复） | 分别在 `reagentc /disable` 和 `reagentc /enable` 之后运行检测，对照 `reagentc /info` 和 `dir /a C:\Windows\System32\Recovery` |
| `system.managed-device` | 排除内部注册项的名单来自社区工具 | 在家庭中文版、只登录了微软账户、只在 Office 里添加了工作账户的电脑上，都应判为「个人电脑」 |
| `security.secureboot-ca2023` | 传统 BIOS 电脑上 `Confirm-SecureBootUEFI` 抛出的具体异常 | 在一台传统 BIOS 启动的电脑上运行 |
| `hardware.system-disk-type` | Intel RST / VMD 的 RAID 模式下报的 BusType、MediaType、型号名是什么：现在 RAID 总线下，除非 MediaType 报的是 SSD，或者型号名里看得出 SSD / NVMe，一律判 unsure（界面显示「没查出来」）；eMMC 小本报的总线类型 | 在开了 VMD / RAID On 的新笔记本和 eMMC 小本上运行，对照任务管理器「性能」页的磁盘类型；如果 RAID 下能可靠拿到 SSD，就把 unsure 收窄 |
| `hardware.memory-size` | 板载内存、部分 BIOS 报的插槽数不准；虚拟机里插槽数是 0 | 在板载内存的笔记本上对照任务管理器 |
| `hardware.battery-health` | 接了 UPS 的台式机会不会把 UPS 当成电池；电池彻底坏了（系统显示「0% 可用」）时，电池报告里的满电容量是不是 0（现在按 0 判为「老化严重」） | 在接 UPS 的台式机上运行；找一台电池坏了的旧笔记本运行 |
| `hardware.device-problems` 重装后 | 刚重装完系统、还没装驱动时会出现哪些代码和名字：没驱动的无线网卡、有线网卡是不是代码 28，在中文系统里是不是叫「网络控制器」「以太网控制器」，兼容 ID 里有没有 `PCI\CC_02`（脚本靠它认出网卡）；没驱动的 USB 无线网卡报什么名字（它没有类别代码，只能按名字里的 WLAN、Wi-Fi、802.11 这类字样认）；显卡用「Microsoft 基本显示适配器」时服务名是不是 `BasicDisplay`；会不会出现代码 1、24、31 这类少见的代码；Win32_PnPEntity 的 PNPClass 在 Win10、Win11 上是不是都有值（微软文档说这个属性「其实不存在」，脚本在它为空时按 ClassGuid 对应） | 在刚装完 Win10 22H2、Win11 的电脑（或装系统时断了网的虚拟机）上，装驱动之前运行检测，对照设备管理器的「其他设备」和各设备属性里的「设备状态」「硬件 ID」「兼容 ID」；再插一个没装驱动的 USB 无线网卡运行一次 |
| `hardware.device-problems` 拔掉的设备、蓝牙、速度 | 拔掉的设备（U 盘、蓝牙耳机、换下来的显卡）在 Win32_PnPEntity 里是不是 Present 为 false、代码 45（脚本两种都不算问题）；配对手机以后出现的「Bluetooth 外围设备」是不是枚举器 BTHENUM、代码 28（现在只计数、不列名字，结论是「正常」）；电脑自己的蓝牙适配器（Bluetooth 类别，接在 USB 上）出错时是否照常报出、名字对不对；健康的电脑上有没有一直带问题代码、设备管理器里默认看不到的隐藏设备（比如 WAN Miniport、Teredo、PS/2 键盘鼠标），有的话要考虑算作「不算问题」；设备很多（插过上百个 U 盘、装过很多虚拟网卡）的电脑上查询要多久（检测的超时是 30 秒） | 插拔几个 U 盘、配对一台手机和一副蓝牙耳机后运行，对照设备管理器（「查看 → 显示隐藏的设备」）；在机械硬盘的老电脑上计时：`Measure-Command { Get-CimInstance Win32_PnPEntity -Filter "(ConfigManagerErrorCode <> 0 AND ConfigManagerErrorCode <> 45) OR Service = 'BasicDisplay' OR ClassGuid = '{4d36e968-e325-11ce-bfc1-08002be10318}'" }`，再和不带 `-Filter` 的查询比一比 |
| `boot.last-boot-duration` | 开着快速启动时，「关机再开机」会不会记录事件 100；现在按 MainPathBootTime（按下电源到出现桌面）判断快慢，要确认它是否包含停在登录界面、输入密码的时间（包含的话，设了密码的电脑会被误判为慢）；装完更新后的第一次开机，事件 100 的 `BootIsRebootAfterInstall` 是不是 true（检测靠它跳过这种开机，10 条全是时给 after-update） | 开快速启动，关机再开机后运行；在登录界面停一分钟再输密码，对照 MainPathBootTime 和 UserLogonWaitDuration；装一次需要重启的系统更新，重启后在事件查看器里看这次的事件 100，再运行检测，`boot_when` 应该是更早的一次普通开机 |
| `system.reliability-recent` | 精简系统可能关掉了可靠性数据收集，这时会误显示「正常」 | 在关闭了 RacTask 计划任务的电脑上运行 |
| `disk.error-events` | 现在按盘号（`\Device\HarddiskN`）和盘符排除 USB 盘和已经拔掉的盘，要确认：153 的插入字符串里确实有 `\Device\HarddiskN`；Ntfs 98 的「需要完整磁盘检查」是错误 / 警告级别、插入字符串里有盘符（「卷正常」那条是信息级别，不计数）；U 盘上的 Ntfs 55 能按盘符排除 | 拔一次正在读写的 U 盘后运行，看 `excluded_removable`；在事件查看器里对照一条真实的 153 和 98 |
| `audio.service`、小工具「重启音频服务」 | 家用电脑上两个音频服务的默认启动类型是不是都是「自动」（修复「恢复 Windows 音频服务」按这个改）；重启 Endpoint Builder 时 Windows Audio 会跟着停，脚本再把它启动起来，要确认声音马上恢复、正在进行的语音通话只断一下 | 放着音乐运行「重启音频服务」；在「服务」里把 Windows Audio 设成禁用后运行「电脑没声音」，执行修复、再重启音频服务，最后在修改日志里撤销 |
| `privacy.microphone`、`privacy.camera` | 「设置」里三个开关和注册表的对应关系：整台电脑的总开关是 HKLM 的 `ConsentStore\<microphone|webcam>`、「允许应用访问」是登录用户的同一个键、「允许桌面应用访问」是它下面的 `NonPackaged`，值都是 Allow / Deny；关掉「允许桌面应用访问麦克风」以后，腾讯会议、微信、钉钉是不是真的听不见（微软说桌面应用有时照样能用） | 在 Win10 22H2、Win11 上逐个关掉这三个开关，每次运行「麦克风、摄像头用不了」，对照 `reg query`；关掉桌面应用的开关后在腾讯会议里试麦克风和摄像头 |
| `system.input-method` | 计划任务 `MsCtfMonitor` 被禁用、注销再登录以后，输入法栏是不是真的没了、ctfmon 是不是没在运行；中文系统上语言列表（`Control Panel\International\User Profile` 的 Languages）是不是 `zh-Hans-CN`；只装了搜狗、微信输入法（删掉了微软拼音）时，中文是不是还在列表里（不在的话会误报「没有中文」） | 禁用这个任务后注销再登录，运行「输入法不见了」；在只留搜狗输入法的电脑上运行一次 |
| `system.keyboard-aids` | 用快捷键打开的筛选键（按住右 Shift 8 秒，弹窗里点「是」）、粘滞键（连按 5 次 Shift）、鼠标键（左 Alt + 左 Shift + Num Lock）是不是都能读出来（CI 只测了用 SystemParametersInfo 直接打开的粘滞键）；在「设置」里关掉以后，重新检查是不是马上显示正常；标准账户登录、输入管理员密码运行小药箱时，读到的是不是登录用户眼前的状态 | 分别用三个快捷键打开后运行「键盘按了没反应」，再在设置里关掉后重新检查；换标准账户登录再做一遍 |
| `disk.hiberfile` | 没有 `HiberFileType` 时按休眠文件占内存的比例判断（不到 30% 算精简版）：新装系统、品牌机预装系统上这个值是不是真的没有，完整版、精简版是不是分别是内存的 40%、20%；有电池、休眠文件是完整版的笔记本判为 battery（默认就是精简版的笔记本判为 reduced）；拆了电池的笔记本靠 PCSystemType 认出来；接了 UPS 的台式机会不会被当成有电池（是的话只是不给按钮）；`powercfg /h /type reduced`、`/type full` 会不会写 HiberFileSizePercent（写了的话撤销时会删回去）；结论和 `powercfg /a` 是否一致 | 在台式机、笔记本上分别运行，对照 `powercfg /a`、`dir /a C:\`（看 hiberfil.sys）和注册表 `HKLM\SYSTEM\CurrentControlSet\Control\Power`；`powercfg /h /type reduced`、`powercfg /h /type full` 之后各运行一次 |
| `system.busy` | 以管理员身份运行时，Get-Process 能不能读出受保护进程（Windows 安全中心的 MsMpEng、360 和火绒的服务进程、csrss）的处理器时间：读不出来的进程不计入，查病毒时就认不出 defender、antivirus；程序说明（FileDescription）和任务管理器「进程」页显示的名字是否一致（中文系统上 svchost.exe 是不是「Windows 服务主进程」、Win32_Service 的 DisplayName 是不是中文）；8 秒里算出的占用和任务管理器是否接近（Win10 21H1 以后任务管理器的「CPU」列按「处理器实用工具」计算，睿频时会比这里高一些）；杀毒软件的进程名（360tray、ZhuDongFangYu、QQPCRTP、HipsDaemon、kxescore 等）在新版本里有没有变；机械硬盘的老电脑上整个检测要多久（超时是 30 秒） | 在 Windows 安全中心里开始「快速扫描」后运行「电脑卡、风扇狂转」，应为 defender；装了 360 或火绒的电脑上让它全盘查杀时运行，应为 antivirus；浏览器里同时放几个视频时运行，应为 browser；每次对照任务管理器 |
| `update.blocked` | 「关更新」的常见软件（Windows Update Blocker、各种「优化大师」、360 的「关闭自动更新」）和教程具体改了哪些地方，检测是不是都认得出：服务被禁用、Windows Update 的登录身份被改成 Guest、组策略、暂停到 2099 年（`FlightSettingsMaxPauseDays` 改大以后在设置里暂停）、设置里的 Windows 更新页面被藏起来；微软只给专业版及以上写了更新策略的文档，家庭版上 `NoAutoUpdate`、`SetDisableUXWUAccess`、`DisableWindowsUpdateAccess`、`UseWUServer` 写进注册表后是不是真的生效（不生效的话结论要改成「写了但家庭版不认」）；`DisableWindowsUpdateAccess` 在没配 WSUS 的电脑上是不是真的让检查更新报 0x8024002F；设置里点「继续更新」能不能清掉暂停到 2099 年的暂停（社区说能，微软没写）；传递优化（DoSvc）在 Win11 家庭版 23H2 以后默认是「手动」还是「自动（延迟启动）」（社区的表对不上；只在被禁用时才报，影响不大）；在设置里正常暂停 1 周，是不是 paused、日期对不对 | 分别用这几种办法关掉更新后运行「系统更新失败」，对照「服务」窗口和 `reg query HKLM\SOFTWARE\Microsoft\WindowsUpdate\UX\Settings`；在家庭版上逐个写这几条策略，再在设置里点「检查更新」看效果 |
| `update.history` | 读出来的记录和「设置 → Windows 更新 → 更新历史记录」是否一致，标题是不是中文；Win11 24H2 起通过新的更新方式装的累积更新是否也在记录里（微软没写明）；装失败的更新下个月的累积更新装上以后，是不是不再报；错误代码的分类准不准（尤其是 0x80070643、0x800F0922 这两个常见的：0x80070643 只有恢复环境更新 KB5034441、KB5042320 单独说明，别的归到「别的代码」）；记录很多的老电脑上要多久（每次读 100 条、读到 30 天以前就停，超时 60 秒） | 在装失败过更新的电脑上运行，对照更新历史记录；在机械硬盘的老电脑上计时 |
| `disk.smart-health` | 查不到健康状态（Unknown）的内置盘现在判为 incomplete（界面显示「没查出来」），不再算进「状态良好」：要确认 RAID / Intel RST 下系统盘是不是 Unknown；读卡器里的 SD 卡、eMMC 系统盘各报什么 BusType（SD / MMC 上只有系统盘算内置） | 在开了 RAID 的电脑、带读卡器的笔记本、eMMC 小本上运行 |
| `security.bitlocker-status` | 「等待激活」（已加密但没启用保护）现在靠 `GetKeyProtectors` 返回空来识别；「保护已暂停」有保护器，仍按「已开启」处理 | 在只用本地账户装好的 Win11 24H2 家庭版上运行，对照 `manage-bde -status` 里的「密钥保护器」；再在暂停了 BitLocker 的专业版上运行 |
| `network.proxy-dead` | 拨号、VPN 连接的代理：`Internet Settings\Connections\<连接名>` 的格式是否和局域网的一样；连着 PPPoE 时 WinINet 是否真的用这个连接的设置（微软 IE 团队博客是这么说的） | 在直接 PPPoE 拨号的电脑上，用 v2rayN 打开系统代理后强行结束它，运行检测，看结果是不是 dead-dialup（「拨号或 VPN 连接「宽带连接」的代理指向本机……」），`dialup_proxy` 里有没有这个连接 |
| `network.connectivity` 飞行模式 | 飞行模式靠 `HKLM\SYSTEM\CurrentControlSet\Control\RadioManagement\SystemRadioState` 这个键的默认值（1 = 开、0 = 关）判断，微软没有公开，来自社区经验和微软论坛版主的说明：要确认 Win10 22H2、Win11 上开关飞行模式时它是不是马上跟着变、是不是在别处（脚本也兼容 RadioManagement 下名为 SystemRadioState 的值）；飞行模式下再单独打开 WiFi 时是什么（检测只在什么都没连上时才用它）；没有无线网卡的台式机上是什么；只关 WiFi、或者旧笔记本拨了硬件无线开关时，WiFi 网卡的 `OperationalStatusDownLowPowerState`（事实 `wifi_low_power`）是不是 true——可靠的话可以单独给一个「WiFi 被关掉了」的结论 | 在 Win10 22H2 和 Win11 的笔记本上分别：开飞行模式、关飞行模式、飞行模式下再打开 WiFi、只关 WiFi，每次运行 `Get-ItemProperty 'HKLM:\SYSTEM\CurrentControlSet\Control\RadioManagement\SystemRadioState'` 和检测，对照 `airplane_mode`、`wifi_low_power` 和结论（应依次是 airplane-mode、正常、正常、not-connected-wifi） |
| `network.connectivity` 网卡分类 | 实体网卡按 `HardwareInterface` 或 `ConnectorPresent` 为真认，类型按 `NdisPhysicalMedium`：要确认 USB 网卡、手机 USB 共享（RNDIS）、Hyper-V 外部交换机（实体网卡没有地址、地址在 vEthernet 上）、VMware / VirtualBox 的虚拟网卡、Clash / WireGuard 这类 TUN 网卡、蓝牙网络、WiFi 7 网卡（一张卡会出现好几个适配器）是否归类正确；CI 那种 Hyper-V 虚拟机里的网卡算不算实体；`Status` 是不是总是英文的 Up / Disconnected / Disabled（脚本先看数字，再看它） | 在装了这些软件的电脑上运行 `Get-NetAdapter \| Format-List Name, InterfaceDescription, Status, State, InterfaceOperationalStatus, HardwareInterface, ConnectorPresent, Virtual, EndPointInterface, NdisPhysicalMedium, PhysicalMediaType, InterfaceType`，对照检测的 `adapter_count`、`adapter`、`adapter_kind`；拔掉网线、断开 WiFi、禁用网卡各运行一次 |
| `network.connectivity` 路由器 | 常见的路由器（TP-Link、华为、小米、中兴，以及当路由器用的光猫）在局域网里回不回 ping；不回 ping 时，刚 ping 完邻居缓存（`Get-NetNeighbor`）里路由器是不是 Reachable（脚本靠它认出路由器还活着；缓存是 Stale、Delay 时不算，这时要靠 DNS 查得到来证明路由器是通的）；信号差的 WiFi 上 3 次、每次 700 毫秒够不够 | 在几种路由器上运行检测，看 `gateway_ping`、`gateway_arp`；在路由器设置里关掉「允许局域网 ping」再运行；拔掉路由器的电源再运行一次，应为 gateway-unreachable；断开再连上 WiFi 后马上运行一次 |
| `network.connectivity` Windows 的结论 | `Get-NetConnectionProfile` 的 IPv4Connectivity / IPv6Connectivity 在这些情况下是什么，检测是否给出括号里的结论：酒店、校园网还没网页登录（internet-unconfirmed）；宽带欠费、运营商把网页转到缴费页（internet-unconfirmed）；光猫的光纤断了、路由器是通的（no-internet，并提示打运营商电话）；系统代理指向一个已经关掉的代理软件（NCSI 走代理测试失败时说不说「没网」：会的话是 internet-unconfirmed，接着由代理检查找出来）；DNS 手动设成用不了的地址（dns-suspect）；`EnableActiveProbing` 改成 0（ncsi-off）；Win11 上 NCSI 从 NLA 服务挪到了网络列表服务，这些值和 Win10 是否一样 | 在对应的网络里运行 `Get-NetConnectionProfile \| Format-List InterfaceAlias, IPv4Connectivity, IPv6Connectivity` 和检测；对照「事件查看器 → 应用程序和服务日志 → Microsoft → Windows → NCSI → Operational」里 Capability change 的 ChangeReason |
| `network.connectivity` 拨号和手动设置 | 电脑自己 PPPoE 拨号（光猫是桥接）时：没拨号时有线网卡是不是 169.254 开头（现在报 no-address，文字里提醒先拨号），拨上以后「宽带连接」的连接配置是不是 Internet（应为正常）；在「设置」里手动设置的 IP 是不是 PrefixOrigin Manual，手动设置的 DNS（包括 Win11 的 DNS over HTTPS）是不是写在 `Tcpip\Parameters\Interfaces\{网卡 GUID}` 的 NameServer 里（脚本靠它认「DNS 是手动设置的」）；VPN、加速器改的 DNS 写在哪里 | 在 PPPoE 拨号的电脑上断开、连上「宽带连接」各运行一次；在「设置」里把 IP、DNS 改成手动后运行，看注册表和 `manual_address`、`manual_dns`，再改回自动 |
