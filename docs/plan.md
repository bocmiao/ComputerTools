> 项目暂定名：**电脑小药箱**（名字待定，见第十一节）
> 性质：免费、开源的 Windows 电脑维护工具
> 编写日期：2026-09-26
> 依据：前一份《电脑维护工具箱_竞品调研与分析》

## 〇、一页纸摘要

| 问题           | 回答                                                         |
| -------------- | ------------------------------------------------------------ |
| **做什么**     | 一个 Windows 桌面程序（exe）。普通人点「上不了网」「C 盘满了」「打印机连不上」就能自己修好电脑；另外提供装软件、常用设置、重装前后的备份与恢复 |
| **给谁用**     | 不懂电脑的普通用户，以及经常帮亲友修电脑的「懂哥」           |
| **凭什么**     | 国内好用的维护工具要么闭源、停更，要么捆绑广告；海外开源工具是英文的，也不管国内的问题。我们做**开源、纯净、中文、每一步都能撤销**的版本 |
| **怎么做**     | Tauri 2 + Vue 3 做界面，PowerShell 做执行层。所有维护功能写成数据文件（检测、执行、撤销三段），不写死在代码里 |
| **不做什么**   | 激活、广告、遥测、关杀软、永久禁更新、删系统组件、第三方系统镜像、驱动库、杀毒、PE 等。详见**第五节**，每一条都写了原因 |
| **节奏**       | 约 22 周出 1.0：v0.1 修复 → v0.2 常用功能 → v0.3 重装助手 → v1.0 签名发布 |
| **怎么算成功** | 修得好（修复项在测试环境里通过率 100%）、不出事（零「把系统改坏」的事故）、被信任（签名、零捆绑、杀软误报能及时解决） |

## 一、为什么做

1. **国内没有一个信得过的维护工具。**
   - 大厂管家功能全，但捆绑、弹窗、会员限速。
   - 一键重装工具普遍锁主页、装全家桶，老毛桃、大白菜都被安全厂商通报过。
   - 口碑好的民间工具要么闭源，要么停更：Dism++ 2023 年起就没再更新，核心代码也从未公开。
2. **现成的开源工具不适合国内普通人。**
   - WinUtil（6.3 万星）、Win11Debloat（5.8 万星）都很成熟，但只有英文，面向技术用户。
   - 它们不覆盖国内的高频问题，比如打印机共享 0x0000011b / 709 报错、微信文件占满 C 盘、LSP 断网。
3. **需求是实打实的。**
   - Win10 已停止支持，但国内仍有约 45% 的电脑在用，升级和重装的需求还会持续几年。
   - C 盘满、开机慢、上不了网，这些问题每天都在发生。

## 二、目标用户与使用场景

| 用户                          | 典型场景                           | 他们需要什么                                              |
| ----------------------------- | ---------------------------------- | --------------------------------------------------------- |
| **小白用户**（主要用户）      | 「电脑突然上不了网了」「C 盘红了」 | 看得懂的中文、一个按钮修好、不怕点坏                      |
| **帮人修电脑的「懂哥」**      | 周末帮亲戚重装、清理电脑           | 一个 U 盘带着走的便携版，批量装软件，重装前后能备份和恢复 |
| **小公司 / 小门店的兼职网管** | 打印机共享、十几台电脑统一设置     | 打印机修复，导出和导入同一套设置                          |

**不是我们的目标用户**：追求极限性能的发烧友、需要统一管理大量电脑的企业 IT。这些需求都有更专业的工具。

## 三、产品原则（所有决策以此为准）

1. **先诊断，后动手**：先告诉用户哪里有问题，征得同意再改。
2. **能撤销**：每一项修改都记入「修改日志」，可以逐项撤销。不能撤销的，事先用红字说明。
3. **说人话**：每个功能都用一句大白话说明「会做什么、有什么影响」。高级用户可以展开看实际执行的命令。
4. **零打扰**：没有广告、捆绑、遥测和账号；不改浏览器主页，也不开机自启。
5. **可验证**：源码公开、构建过程公开、安装包带签名、官网公布校验值，并声明唯一官方下载地址。
6. **只用系统自带或官方来源**：执行动作只用 Windows 自带命令和官方渠道（winget、微软官网、软件官网），不自建下载站。

## 四、我们做什么（功能范围）

优先级说明：

- **P0** 必须有，没有就不发版
- **P1** 当前版本应该有
- **P2** 有余力再做

风险等级：

- 🟢 **安全**：可撤销，无副作用
- 🟡 **注意**：有轻微副作用，或需要重启
- 🔴 **谨慎**：会降低安全性，或不可撤销，必须二次确认

### 4.4 模块三：重装助手（v0.3）

按重装流程分四步：

**第 1 步 · 重装前备份（P0）**

- 导出全部第三方驱动（`pnputil /export-driver`），存到非系统盘或 U 盘。
- 列出桌面、文档、下载、图片的大小，一键复制到指定位置。
- 找到微信、QQ 聊天文件和浏览器书签的位置，提示用户备份。
- 导出已装软件清单：winget 能识别的，重装后可以一键装回。

**第 2 步 · 准备系统（P0）**

- Win11 兼容检测：TPM 2.0、安全启动、CPU 是否在支持列表、内存、硬盘。结论用中文说明。
- 只提供**微软官方**下载页链接，并教用户核对校验值；程序内置校验工具。
- 选重装方式：
  - 不想折腾 → 系统自带的「重置此电脑」。
  - 要全新安装 → 制作启动盘。

**第 3 步 · 制作启动盘（P1）**

- 引导用户从官方渠道下载 **Rufus 或 Ventoy**，我们核对文件的哈希后再启动它们。
- **不把它们的代码打包进我们的程序**（见 5.2 节第 12 条）。
- 自动应答文件生成器，可设置：
  - 本地账户
  - 跳过联网
  - 区域和语言
  - 跳过隐私问答
  - 可选：跳过 Win11 硬件检查。默认关闭，并提示不受微软官方支持。
- 生成的文件放在启动盘根目录。

**第 4 步 · 重装后恢复（P0）**

- 一键导入之前备份的驱动。
- 按之前导出的清单一键装回软件。
- 一键应用之前的常用设置。

### 4.5 网页端（与 v0.2 同期，P1）

网页**不修改用户的电脑**，只做以下几件事：

| 页面           | 作用                                                         |
| -------------- | ------------------------------------------------------------ |
| 官网首页       | 介绍、截图、**唯一官方下载地址**、每个版本的校验值、如何核对签名 |

## 五、我们不做什么，以及为什么

分成两类：**永远不做**（违背原则或有法律、安全风险）和**暂不做**（以后条件成熟可以重新评估）。

### 5.1 永远不做

| #    | 不做的事                                                     | 为什么                                                       | 替代做法                                                   |
| ---- | ------------------------------------------------------------ | ------------------------------------------------------------ | ---------------------------------------------------------- |
| 1    | **激活工具**（KMS、MAS、HEU 等），也不放链接推荐             | ①绕过微软授权，属于侵权；②仓库可能被 GitHub 或 Gitee 整个下架，项目直接没了；③杀软会把整个程序标记为黑客工具，所有功能都受牵连 | 只读显示激活状态，说明数字许可证、正版购买渠道             |
| 2    | **广告、捆绑、推广、会员、导航主页**                         | 这正是国内同类工具失去信任的原因，也是我们立项的初衷。一旦做了，项目就失去了存在的理由 | —                                                          |
| 3    | **遥测、数据上报、账号体系**                                 | 维护工具的权限最高，一旦上报数据就很难自证清白。CCleaner 就出过卖用户数据的事 | 诊断报告只在本地生成，由用户自己决定发不发                 |
| 4    | **关闭或删除 Windows Defender / 安全中心**                   | ①让用户电脑失去保护；②这类功能是杀软误报的头号原因，还会拖累程序其他功能的信誉 | 用户装了第三方杀软时，Defender 会自动让位，不需要手动关    |
| 5    | **永久禁用 Windows 更新**                                    | 不打安全补丁的电脑，是勒索病毒最容易得手的目标               | 提供有期限的「暂停更新」，以及「修复更新失败」             |
| 6    | **删除系统组件或精简系统**（删 Edge、WebView2、应用商店、系统服务，制作精简镜像） | ①很可能导致大版本升级失败、系统功能缺失，出了问题用户也不知道原因；②很多软件依赖 WebView2，**包括我们自己的程序**；③Atlas OS 等项目的争议就是前车之鉴 | 只卸载系统本身允许卸载的预装应用（比如游戏、资讯类）       |
| 7    | **提供或推荐第三方修改版系统镜像**（Ghost 版、精简版、「纯净版」） | 来源无法验证，历史上多次被发现夹带后门、锁主页、预装推广     | 只指向微软官方镜像，并教用户核对校验值                     |
| 8    | **从网上实时下载脚本并直接执行**（类似 `irm \| iex` 的方式） | ①域名一旦被劫持或仿冒，用户就会执行恶意代码（MAS 就出过这种事）；②这种方式极易被杀软误报 | 所有脚本随安装包一起发布、一起签名；更新脚本就等于发新版本 |
| 9    | **修改浏览器主页、默认浏览器、默认搜索引擎**                 | 这是流氓软件的典型行为，哪怕是「好意」也不做                 | —                                                          |
| 10   | **静默自动更新自己**                                         | 用户应该知道自己电脑上的程序什么时候发生了变化               | 启动时检查新版本并提示，由用户决定是否下载                 |

### 5.2 暂不做（以后可重新评估）

| #    | 暂不做的事                                   | 为什么现在不做                                               | 替代做法                                                     | 什么时候再考虑                                     |
| ---- | -------------------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ | -------------------------------------------------- |
| 11   | **驱动下载库 / 一键装驱动**                  | ①要维护海量驱动，工作量是天文数字；②驱动分发涉及版权；③装错驱动可能蓝屏、开不了机；④驱动更新通道本身就是攻击目标，驱动人生 2018 年被劫持植入过挖矿木马 | Windows 更新的可选驱动、品牌官网链接、驱动备份与恢复         | 基本不会做                                         |
| 12   | **内置 PE / 自己做 PE 启动盘**               | ①工作量大；②微 PE、Edgeless 等已经做得很好；③WinPE 组件的再分发有授权限制；④把 Rufus、Ventoy（GPL 许可）打包进来会引发许可证问题 | 引导用户使用 Ventoy 或 Rufus 配合官方镜像，推荐可信的 PE     | 1.0 之后看需求                                     |
| 13   | **实时温度监控、风扇控制、硬件跑分**         | 读取温度要加载内核驱动。常用的 WinRing0 驱动从 2025 年 3 月起被 Defender 标记为黑客工具（LibreHardwareMonitor、FanControl 都受了影响）；另外图吧工具箱已经做得很好 | 显示硬件配置和硬盘健康；推荐图吧工具箱、CrystalDiskInfo      | 等无害的新驱动方案（如 PawnIO）成熟后再评估        |
| 14   | **杀毒、木马查杀**                           | 专业门槛极高，做不好反而给用户虚假的安全感                   | 一键调用 Defender 全盘扫描；推荐火绒等可信的免费杀软         | 不做                                               |
| 15   | **「一键加速」「内存释放」「注册表清理」**   | 效果可疑，甚至有害：释放内存会导致程序变卡，注册表清理微软明确不支持。这类功能是「管家」制造焦虑的套路 | 只做有实际效果的清理（磁盘空间）和启动项管理                 | 不做                                               |
| 16   | **在现有系统上强行升级 Win11，绕过硬件限制** | 属于不受支持的安装方式，以后可能收不到大版本更新，出问题难排查 | 自动应答生成器里提供「跳过硬件检查」选项，默认关闭，写明风险 | 视微软政策再评估                                   |
| 17   | **支持 Win7 / Win8**                         | ①技术栈不支持（WebView2 和 .NET 8 都已放弃 Win7）；②国内只占约 4%；③系统本身已停止支持多年，维护它们意义不大 | 在官网上建议 Win7 用户升级或重装                             | 不做                                               |
| 18   | **AI 智能诊断**                              | 要联网和付 API 费用，和「不上报数据」的原则有冲突，还会增加成本 | 用本地规则库做诊断（症状 → 检测 → 修复）                     | 1.0 之后，可考虑「用户自愿、本地脱敏后」的可选功能 |
| 19   | **远程协助**                                 | 安全敏感，而且容易被诈骗分子利用                             | 推荐 Windows 自带的「快速助手」                              | 不做                                               |
| 20   | **Mac / Linux 版本**                         | 问题场景完全不同，会分散精力                                 | —                                                            | 不做                                               |
| 21   | **企业批量管理**（域、组策略、统一下发）     | 目标用户不是企业；这方面有专业方案                           | 提供设置导出和导入（P2），满足小门店的需求                   | 不做                                               |

## 六、怎么做（技术方案）

### 6.1 整体架构

```
┌──────────────────────────────────────────────┐
│  界面层  Vue 3 + TypeScript（和网页端共用组件）   │
├──────────────────────────────────────────────┤
│  外壳层  Tauri 2（Rust）                         │
│   · 功能数据加载与校验                            │
│   · 执行调度：检测 → 确认 → 执行 → 记录日志        │
│   · 修改日志 / 撤销 / 还原点                      │
│   · 少量系统接口调用（窗口溯源、硬件信息）          │
├──────────────────────────────────────────────┤
│  执行层  PowerShell 脚本（随安装包签名发布）        │
│         + Windows 自带命令（netsh、sfc、DISM、     │
│           pnputil、winget、powercfg……）          │
├──────────────────────────────────────────────┤
│  数据层  功能定义（YAML/JSON）· 软件清单 ·         │
│         蓝屏错误码中文解释 · 打印机错误码对照       │
└──────────────────────────────────────────────┘
```

### 6.2 核心设计：功能即数据

每个维护功能写成一个数据文件，包含「检测、执行、撤销」三段。**新增功能基本不用改程序代码**，社区也能直接提交新的修复项。

示例（关闭休眠文件）：

```yaml
id: disk.hibernation.off
名称: 关闭休眠，释放 C 盘空间
分类: C盘满了
说明: 删除休眠文件 hiberfil.sys（通常有几 GB）。关闭后电脑不能「休眠」，但可以正常「睡眠」和关机。
风险: 注意          # 安全 / 注意 / 谨慎
需要管理员: true
需要重启: false
适用系统: [win10, win11]
检测: scripts/disk/hibernation-detect.ps1   # 返回：是否开启、文件大小
执行: scripts/disk/hibernation-off.ps1
撤销: scripts/disk/hibernation-on.ps1        # 不可撤销的写：撤销: 无，并填写「不可撤销原因」
参考: https://learn.microsoft.com/...
```

### 6.3 执行与权限

- **v0.1 采用「启动即请求管理员权限」**。这样实现最简单，也是同类工具的惯例（Dism++ 就是这样）。
- 已知的边界：用户用普通账户登录、再输入管理员密码运行时，修改的「当前用户设置」会落到管理员账户上。v0.1 先检测这种情况并提示用户；如果以后反馈多，再改成「普通权限主程序 + 按需提权的辅助进程」。
- 每次执行前都显示确认框：要改什么、风险等级、能否撤销。执行过程实时输出日志。

### 6.4 修改日志与撤销

- 日志存在程序数据目录，每条记录包含：时间、功能 ID、修改前的值、修改后的值、执行输出、结果。
- 撤销时按功能定义里的「撤销」脚本执行，并把修改前的值传进去。
- 🟡 和 🔴 级操作前先创建还原点。注意：Windows 默认 24 小时内只允许创建一个还原点，程序需要检测并处理这种情况。

### 6.5 代码仓库结构

```
项目根目录/               （仓库名待定）
├─ app/                   Vue 前端（界面）
├─ src-tauri/             Rust 外壳
├─ features/              功能定义 YAML（按模块分目录）
├─ scripts/               PowerShell 执行脚本
├─ data/                  软件清单、错误码对照表
├─ website/               官网和教程（VitePress）
├─ tests/                 Pester 脚本测试 + 虚拟机测试清单
└─ .github/workflows/     自动构建、签名、发布
```

### 6.6 测试

| 类型         | 做法                                                         |
| ------------ | ------------------------------------------------------------ |
| 脚本单元测试 | 用 Pester（PowerShell 测试框架）验证每个脚本的检测、执行、撤销逻辑 |
| 虚拟机测试   | Hyper-V 或 VirtualBox 上装 Win10 22H2、Win11 最近两个版本，用快照实现「执行 → 撤销 → 对比」 |
| 故障复现     | 在虚拟机里人为制造故障（设错代理、塞满 C 盘、停掉打印服务），验证能修好 |
| 杀软测试     | 每个版本都用 Defender、火绒、360、腾讯电脑管家检查，并上传 VirusTotal |
| 真机内测     | 找 10–20 位种子用户（包括几位「懂哥」）先用                  |

### 6.7 构建、签名与发布

1. **自动构建**：GitHub Actions 在 Windows 环境上构建，产出安装包和便携版 zip。
2. **代码签名**：申请 SignPath Foundation 的开源免费签名。申请需要项目有一定历史，**尽早启动**。
3. **发布渠道**：
   - GitHub Releases 为主。
   - Gitee 同步镜像，解决国内下载慢的问题。
   - 附 SHA256 校验值文件。
4. **官网**：用 VitePress 做静态站。可以放在你已备案的 miao.club 子域名下，也可以放在 GitHub Pages。**安装包不要放在自己服务器上**，3M 带宽扛不住下载，统一走 GitHub 和 Gitee。
5. **提前报误报**：每个版本发布前向微软和主流杀软提交误报申诉。

### 6.8 许可证

- **建议 GPL-3.0**：
  - 防止别人闭源套壳、加广告再分发。国内倒卖改版的情况很常见，GPL 要求改版也必须公开源码。
  - 可以合法吸收 GPL 代码。
- 可以参考和复用的 MIT 项目：WinUtil、Win11Debloat、Sophia Script、unattend-generator。保留原版权声明即可。
- **不能复制代码的项目**：privacy.sexy（AGPL，会传染整个项目）、tiny11builder（没有许可证）、Winhance（非标准许可）。
