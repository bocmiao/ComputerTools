## 〇、一页纸摘要

| 问题 | 回答 |
|---|---|
| **做什么** | 一个 Windows 桌面程序（exe）。普通人按症状点「上不了网」「C 盘满了」「打印机连不上」，就能自己查出原因、修好电脑；懂哥可以把它装在 U 盘里，批量处理亲友的电脑。另外提供装软件、常用设置、重装前后的备份与恢复 |
| **给谁用** | 不懂电脑的普通用户，以及经常帮亲友修电脑的「懂哥」 |
| **凭什么** | 大厂管家捆绑、弹窗、会员；民间工具闭源或停更；海外开源工具只有英文、面向技术用户，也不管国内的问题。我们做**开源、纯净、中文、以「按症状修复」为核心、每一步都能撤销**的版本 |
| **怎么做** | Tauri 2 + Vue 3 做界面，Rust 和 PowerShell 做执行层。功能写成两层数据：症状诊断树 + 原子修复。常见修改由引擎执行并自动记下原值，撤销时原样写回 |
| **不做什么** | 激活、广告、遥测、关杀软、永久禁更新、删系统组件、第三方系统镜像、驱动库、杀毒、PE、关 UAC 等。详见**第五节**，每一条都写了原因 |
| **节奏** | 约 24 周出 1.0：v0.0 只读体检版 → v0.1 修复 → v0.2 常用与懂哥功能 → v1.0 签名发布。重装助手全流程放到 1.x |
| **怎么算成功** | 修得好（修复项在测试环境里通过率 100%，修完自动复查）、不出事（零「把系统改坏」、零「丢用户数据」）、被信任（签名、零捆绑、杀软误报能及时解决） |

## 一、为什么做

1. **国内没有一个信得过的维护工具。**
   - 大厂管家功能全，但捆绑、弹窗、会员限速。
   - 一键重装工具普遍锁主页、装全家桶，老毛桃、大白菜都被安全厂商通报过。
   - 口碑好的民间工具要么闭源，要么停更：Dism++ 2023 年起就没再更新，核心代码也从未公开。
   - 〔待补：竞品调研结论〕
2. **现成的开源工具不适合国内普通人。**
   - WinUtil、Win11Debloat 都很成熟，但只有英文，面向技术用户，主要做「精简和调优」，不做「按症状修复」。
   - 它们不覆盖国内的高频问题，比如打印机共享 0x0000011b / 709 报错、微信文件占满 C 盘、LSP 断网、梯子卸载后留下的代理设置。
3. **需求是实打实的，而且在变多。**
   - Win10 的主流支持已在 2025-10-14 结束，但国内仍有约 45% 的电脑在用。微软 2026 年 6 月把消费者 ESU（扩展安全更新）延长到 2027-10-12，把电脑设置同步到微软账户即可免费登记（国内能否登记需实测）。升级、登记 ESU 和重装的需求还会持续几年。
   - Win11 24H2 之后出现了一批新问题：专业版默认要求 SMB 签名导致共享打不开、自动开启设备加密（BitLocker）导致重装后要恢复密钥、打印机默认改用系统自带的通用驱动等。
   - C 盘满、开机慢、上不了网，这些问题每天都在发生。
4. **很多电脑是被「优化」工具改坏的。** 精简版系统、一键关更新、关 Defender、锁主页，留下的问题没人收拾。「把系统改回正常」本身就是需求，也是我们和精简类工具的根本区别。

## 二、目标用户与使用场景

| 用户 | 典型场景 | 他们需要什么 |
|---|---|---|
| **小白用户**（主要用户） | 「电脑突然上不了网了」「C 盘红了」「打印机又连不上了」 | 看得懂的中文；一个按钮修好；不怕点坏；修不好时知道该找谁 |
| **帮人修电脑的「懂哥」** | 周末帮亲戚重装、清理电脑；亲戚在微信上发来一张报错截图 | U 盘便携版；一键执行自己的标准流程；不用远程控制也能远程「开药方」；重装前后能备份和恢复 |
| **小公司 / 小门店的兼职网管** | 打印机共享、共享文件夹、十几台电脑统一设置 | 打印机和共享修复；同一套设置在多台电脑上复用 |
| **买新电脑或二手电脑的人**（新增） | 「这台电脑是不是新的？配置对不对？电池还行吗？」 | 验机：硬盘通电时间、电池损耗、配置核对 |

**不是我们的目标用户**：追求极限性能的发烧友、需要统一管理大量电脑的企业 IT。这些需求都有更专业的工具。

## 三、产品原则（所有决策以此为准）

1. **先诊断，后动手**：先告诉用户哪里有问题，征得同意再改。
2. **能撤销**：每一项修改都记入「修改日志」，可以逐项撤销。不能撤销的，事先用红字说明。
3. **说人话**：每个功能都用一句大白话说明「会做什么、有什么影响」。高级用户可以展开看实际执行的命令和改动的注册表项。
4. **零打扰**：没有广告、捆绑、遥测和账号；不改浏览器主页，不开机自启，不常驻后台。
5. **可验证**：源码公开、构建过程公开、安装包带签名、官网公布校验值，并声明唯一官方下载地址。
6. **只用系统自带或官方来源**：执行动作只用 Windows 自带命令和官方渠道（winget、微软官网、软件官网），不自建下载站。少数必须的第三方开源组件（如 smartmontools）固定版本、校验哈希，并在官网列明。
7. **不制造焦虑**（新增）：没问题就说「一切正常」；不打分，不把无关紧要的项目标红，不用「发现 38 个问题」吓人。
8. **知道边界**（新增）：遇到硬件故障、单位管理的电脑、超出能力的情况，直接说明，并告诉用户下一步找谁（品牌售后、运营商、懂哥）。
9. **用户文件零容忍**（新增）：凡是会删除用户文件的操作，都逐项列出、逐项确认、默认不勾选。
10. **优先用系统自己的机制**（新增）：系统自带的开关能用就用，不自己另造（例如存储感知、任务管理器同款的启动项开关、Windows 更新修复）。这样即使卸载了小药箱，用户在系统里依然看得到、改得回。

## 四、我们做什么（功能范围）

优先级说明：

- **P0** 必须有，没有就不发版
- **P1** 当前版本应该有
- **P2** 有余力再做

风险等级：

- 🟢 **安全**：可撤销，无副作用
- 🟡 **注意**：有轻微副作用，或需要重启
- 🔴 **谨慎**：会降低安全性，或不可撤销，必须二次确认

版本：每项标注计划进入的版本（v0.0 / v0.1 / v0.2 / v1.0 / 1.x），排期见第八节。

| 深色模式 / 高分屏 / 长辈模式（大字、少选项） | — | P2 | 1.x |

### 4.2 模块一：按症状修复（核心）

v0.1 先做 4 个：上不了网、C 盘满了、开机慢、打印机与共享。其余的在 v0.2 补齐。

| 症状 | 检测什么 | 修复做什么 | 撤销方式 | 风险 | 优先级 · 版本 |
|---|---|---|---|---|---|
| **上不了网** | 按链路顺序检查，断在哪一环就停在哪一环：网卡与飞行模式 → 有没有拿到 IP（169.254 开头说明路由器没分配地址）→ 网关 → 外网 → DNS 解析 → 代理（指向本机某个端口，但那里没有程序在监听，多半是梯子或加速器卸载后的残留）→ hosts → Winsock / LSP → 系统时间（时间不对，所有 HTTPS 网站都会报错）→ 是不是要网页登录的网络（校园网、酒店 Wi-Fi） | 画出「电脑 → 路由器 → 宽带 → 网站」的链路图，标出断在哪里。断在宽带，就直接说「不是电脑的问题，请联系运营商（电信 10000、移动 10086、联通 10010）」。电脑这边的修复：刷新 DNS；关闭已失效的代理（系统代理和 WinHTTP 代理）；同步系统时间；打开网络登录页（`msftconnecttest.com/redirect`）；重置 Winsock 和 TCP/IP（需要重启）；可选改用公共 DNS | 代理、DNS 可撤销；Winsock 重置不可撤销，但没有坏处 | 🟡 | P0 · v0.1 |
| **C 盘满了** | 各大目录的占用：临时文件、更新缓存、回收站、休眠文件、传递优化缓存、Windows.old、内存转储文件、微信（3.x 是 `WeChat Files`，4.x 是 `xwechat_files`）和 QQ 的文件目录；外加「最大的文件夹」只读分析 | **治标**（分项勾选）：临时文件、更新下载缓存、传递优化缓存、组件存储清理（`DISM /StartComponentCleanup`，不加 `/ResetBase`）；休眠文件可以选「关闭」，也可以选「缩小」（`powercfg /h /type reduced`，保留快速启动）。**要格外确认的**：回收站（先让用户看到里面有什么、有多大，默认不勾选）；Windows.old（先扫描里面有没有用户文件——没格式化就装了新系统时，旧桌面和文档只在这里）；内存转储文件（先做完蓝屏分析，再提示可以清理）。**治本**：开启存储感知；把新内容的默认保存位置改到其他盘；用系统自带的「位置」选项卡迁移桌面、文档、下载；引导用户在微信、QQ 自己的设置里改存储位置 | 缓存清理不需要撤销；休眠、存储感知、保存位置可以撤销；回收站、Windows.old 删了就回不来（红字说明） | 🟢 / 🟡；删 Windows.old 为 🔴 | P0 · v0.1 |
| **开机慢** | 读系统事件日志（Diagnostics-Performance：事件 100 记录每次开机的耗时，101–110 记录是谁拖慢了开机）；启动项（注册表 Run 项、启动文件夹）、第三方计划任务、第三方服务，标出新增的和可疑的；硬件瓶颈：系统盘是不是机械硬盘、内存是不是只有 4GB 或更少 | 给出「上次开机 85 秒，其中 XX 拖慢了 12 秒」这样的结论；**禁用**（不删除）选中的启动项，用和任务管理器相同的机制（StartupApproved），用户在任务管理器里也能改回来；服务改成「手动」，不改成「禁用」；下次开机后给出前后对比。硬件是瓶颈就直说：「换一块固态硬盘最有效」 | 可撤销，重新启用即可 | 🟢 | P0 · v0.1 |
| **打印机共享连不上** | 先问一句：「这台电脑是**共享打印机的主机**，还是要**连别人共享的打印机**？」两边的修复不一样。然后按错误码（0x0000011b / 0x00000709 等）检测打印服务、网络发现、系统版本；再看打印机本身有没有网口或 Wi-Fi | 主机这边：写入 0x11b 对应的兼容设置（`RpcAuthnLevelPrivacyEnabled`）。连接的那台：Win11 22H2 起，连接旧系统主机会报 709，改用命名管道方式的 RPC 连接。两边都可以做：重启打印服务（Print Spooler）、清理卡住的打印队列、开启网络发现和文件共享。**打印机本身能联网的，优先建议直接按 IP 添加**，从根上绕开共享的问题 | 注册表可撤销 | 🔴（0x11b 的修复会降低打印安全性，要明确提示） | P0 · v0.1 |
| **共享文件夹打不开**（新增） | 错误提示（0x80070035「找不到网络路径」、「组织的安全策略阻止未经身份验证的来宾访问」等）；双方的系统版本和版本类型（24H2 起，专业版和企业版默认要求 SMB 签名、禁止来宾访问，家庭版不要求签名）；网络发现；共享的那台是否设置了账号密码 | **首选**：给共享的那台设置账号密码访问，安全又一劳永逸。确实只能用来宾访问时，才提供「关闭 SMB 签名要求」「允许不安全的来宾登录」（🔴，写明风险）。另外：开启网络发现；在凭据管理器里清掉保存错了的密码 | 可撤销 | 🟡 / 🔴 | P0 · v0.1 |
| **系统更新失败** | 更新服务的状态；最近失败的错误码（附中文解释）；更新是不是被策略、服务或暂停天数禁用了（见 4.3）；WinRE 与恢复分区（2024 年 KB5034441 报 0x80070643，就是因为恢复分区太小）；磁盘空间；是否在等待重启 | 重置更新组件（停服务、重命名缓存目录、重启服务）；运行 `sfc /scannow` 和 `DISM /RestoreHealth`；被禁用的恢复为默认 | 更新缓存会自动重建；恢复默认的操作可以撤销 | 🟡 | P0 · v0.2 |
| **系统文件损坏 / 小毛病多** | — | 按「修复阶梯」从轻到重（见 4.6 第 0 步）：SFC 和 DISM → Win11 的「通过 Windows 更新重装当前系统」（保留软件和文件）→ 覆盖安装 → 重置此电脑。结果翻译成中文 | 前两步不需要撤销 | 🟢（后几步为 🟡） | P0 · v0.2 |
| **蓝屏了** | 蓝屏记录（dump 文件列表、事件日志里的蓝屏事件）；非正常关机（Kernel-Power 41，常见于电源、过热）；硬件错误（WHEA-Logger）；硬盘坏道事件 | 列出最近蓝屏的时间和错误码，用中文解释常见原因（驱动、内存、硬盘、电源）和下一步；可以预约系统自带的内存诊断（`mdsched`，会重启），下次打开时读出结果 | 只读，不修改系统 | 🟢 | P1 · v0.2 |

| **设备不正常 / 缺驱动** | 设备管理器里有问题的设备；特别标出「Microsoft 基本显示适配器」（显卡驱动没装，刚重装完常见）和网卡；用硬件 ID 查出设备的厂商和名称 | 引导用户到 Windows 更新的「可选更新」，或按品牌和型号直达官网的驱动页 | 只读 | 🟢 | P1 · v0.2 |
| **声音、麦克风、摄像头、输入法**（原 P2） | 默认播放设备（常见情况：声音从显示器的 HDMI 输出了）；Windows 隐私权限（「允许桌面应用访问麦克风 / 摄像头」被关掉了，腾讯会议没声音多半是这个原因）；相关服务的状态；输入法进程（ctfmon） | 切换默认设备；打开对应的隐私设置；重启服务；恢复输入法进程；打开系统自带的疑难解答〔待补：「获取帮助」现状〕 | 可撤销或不需要 | 🟢 | P1 · v0.2 |

> 关于打印驱动（新增）：2026-07-01 起，Windows 默认优先使用系统自带的 IPP 通用打印驱动；2027-07-01 起，第三方打印驱动除了安全修复以外，不再通过 Windows 更新更新。可能出现「打印机能用，但双面、纸盒这些选项没了」的情况，需要单独检测并说明。

### 4.6 模块五：重装助手（1.x；「重装前必须备份」的部分提前到 v0.2）

**第 0 步 · 先别急着重装：修复阶梯（P0）**

很多「要重装」的情况，用更轻的办法就能解决。按从轻到重的顺序推荐：

1. SFC / DISM 修复。
2. Win11 自带的「通过 Windows 更新重装当前系统」，保留软件和文件。
3. 挂载微软官方 ISO 覆盖安装，保留软件、文件和设置。
4. 重置此电脑，可以选「云下载」。前提是 WinRE 正常，体检会提前检查。
5. 全新安装。

**第 1 步 · 重装前备份（P0，v0.2 提前做）**

- **BitLocker 恢复密钥（第一项，强制）**：24H2 起，用微软账户完成开机设置的电脑，很多会自动开启设备加密。重装、换主板、刷 BIOS 之后，会被要求输入恢复密钥，而用户往往不知道密钥存在自己的微软账户里；数据盘也加密了的话，重装后直接打不开。做法：显示恢复密钥并保存到 U 盘，或者告诉用户去 aka.ms/myrecoverykey 查；必要时先解密。
- **版本与激活**：读取主板里 OEM 密钥对应的版本（`OA3xOriginalProductKeyDescription`），告诉用户「你的电脑出厂是家庭中文版，重装时选这个版本才能自动激活」。这能切断「重装 → 没激活 → 去搜激活工具」这条路，和第五节第 1 条一脉相承。预装了 Office 家庭和学生版的电脑，提醒用户先确认它已经绑定到微软账户。
- **驱动**：导出全部第三方驱动（`pnputil /export-driver`），存到非系统盘或 U 盘。**网卡驱动和 Intel VMD / RST 存储驱动单独导出到 U 盘根目录**，文件夹名要起得直白：「装完没网就装这个」「装系统找不到硬盘时加载这个」。
- **用户文件**：列出桌面、文档、下载、图片的大小，一键复制到指定位置。**检测 OneDrive**：用户的「桌面」可能其实在 OneDrive 里，部分文件只在云端。提醒不要备份到马上要被格式化的分区。
- **容易忘的**：微信和 QQ 聊天记录、完整的浏览器配置（不只是书签）、输入法词库、Wi-Fi 密码（导出的是明文，只存到 U 盘里，并提示用户）、游戏存档、剪映草稿、邮件客户端数据、付费软件的授权（提醒先解绑）。
- **软件清单**：导出已装软件清单，winget 能识别的，重装后可以一键装回。

**第 2 步 · 准备系统（P0）**

- Win11 兼容检测（见 4.4）。
- 只提供**微软官方**下载页的链接；**内置微软官方 ISO 的哈希库**，直接告诉用户「这是微软原版 Win11 25H2 简体中文 x64 ✓」，不用用户自己比对一长串字符。
- 按修复阶梯选择重装方式。

**第 3 步 · 制作启动盘（P1）**

- 引导用户从官方渠道下载 **Rufus 或 Ventoy**，我们核对文件的哈希后再启动它们；不把它们打包进我们的程序（见 5.2 节第 12 条）。
- 自动应答文件生成器，可设置：
  - 本地账户
  - 跳过联网
  - 区域和语言
  - 跳过隐私问答
  - **阻止自动设备加密**（新增）
  - 可选：跳过 Win11 硬件检查。默认关闭，并提示不受微软官方支持；CPU 不支持 POPCNT / SSE4.2 时不允许勾选。
- 微软在新版本里一直在封堵开机设置时绕过联网、创建本地账户的方法（例如 BypassNRO）。自动应答文件目前仍然是受支持的方式，但**每个 Windows 版本都要回归测试**。
- 生成的文件放在启动盘根目录。

**第 4 步 · 个性化装机说明（P1，新增）**

- 重装时最大的事故是格式化错了分区。先记录当前的磁盘布局，生成「只删除磁盘 0 分区 3（约 237GB，就是现在的 C 盘）」这样的说明。
- 装系统时电脑上看不到我们的程序，所以说明要放到手机上：生成一个二维码，指向官网的装机说明页，参数放在网址 `#` 后面。`#` 后面的内容不会发给服务器，所以既是个性化的，又不用上传任何数据。
- 按品牌显示启动菜单键和进 BIOS 的方法，例如「联想开机按 F12」。
- 兜底技巧：装完系统没有网卡驱动时，用数据线连安卓手机，打开手机的「USB 网络共享」，Windows 用自带的驱动就能上网。

**第 5 步 · 重装后恢复（P0）**

- 一键导入之前备份的驱动。
- 按之前导出的清单一键装回软件。
- 一键应用之前的常用设置（预设套餐）。

## 五、我们不做什么，以及为什么

分成两类：**永远不做**（违背原则或有法律、安全风险）和**暂不做**（以后条件成熟可以重新评估）。v1.1 新增的条目编号接在原有编号之后。

### 5.1 永远不做

| # | 不做的事 | 为什么 | 替代做法 |
|---|---|---|---|
| 1 | **激活工具**（KMS、MAS、HEU 等），也不放链接推荐 | ①绕过微软授权，属于侵权；②仓库可能被 GitHub 或 Gitee 整个下架，项目直接没了；③杀软会把整个程序标记为黑客工具，所有功能都受牵连 | 只读显示激活状态，说明数字许可证、正版购买渠道；重装前告诉用户该选哪个版本才能自动激活（4.6） |
| 2 | **广告、捆绑、推广、会员、导航主页** | 这正是国内同类工具失去信任的原因，也是我们立项的初衷。一旦做了，项目就失去了存在的理由 | — |
| 3 | **遥测、数据上报、账号体系** | 维护工具的权限最高，一旦上报数据就很难自证清白。Avast（当时 CCleaner 的母公司）就曾通过子公司 Jumpshot 出售用户的浏览数据，2024 年被美国 FTC 罚款 1650 万美元 | 诊断报告只在本地生成，默认脱敏，由用户自己决定发不发 |
| 4 | **关闭或删除 Windows Defender / 安全中心** | ①让用户电脑失去保护；②这类功能是杀软误报的头号原因，还会拖累程序其他功能的信誉 | 用户装了第三方杀软时，Defender 会自动让位，不需要手动关 |
| 5 | **永久禁用 Windows 更新** | 不打安全补丁的电脑，是勒索病毒最容易得手的目标 | 提供有期限的「暂停更新」，以及「修复更新失败」 |
| 6 | **删除系统组件或精简系统**（删 Edge、WebView2、应用商店、系统服务，制作精简镜像） | ①很可能导致大版本升级失败、系统功能缺失，出了问题用户也不知道原因；②很多软件依赖 WebView2，**包括我们自己的程序**；③Atlas OS 等项目的争议就是前车之鉴 | 只卸载系统本身允许卸载的预装应用（比如游戏、资讯类）；已经被删坏的，用「反向修复」（4.3）恢复 |
| 7 | **提供或推荐第三方修改版系统镜像**（Ghost 版、精简版、「纯净版」） | 来源无法验证，历史上多次被发现夹带后门、锁主页、预装推广 | 只指向微软官方镜像，并内置官方哈希库自动核对 |
| 8 | **从网上实时下载脚本并直接执行**（类似 `irm \| iex` 的方式） | ①域名一旦被劫持或仿冒，用户就会执行恶意代码（MAS 就出过这种事）；②这种方式极易被杀软误报 | 所有脚本随安装包一起发布、一起签名；更新脚本就等于发新版本 |
| 9 | **修改浏览器主页、默认浏览器、默认搜索引擎** | 这是流氓软件的典型行为，哪怕是「好意」也不做 | 清除劫持（4.3）不算在内：那是把控制权还给浏览器，不是替用户设置 |
| 10 | **静默自动更新自己** | 用户应该知道自己电脑上的程序什么时候发生了变化 | 启动时检查新版本并提示，由用户决定是否下载；检查更新可以关闭（6.9） |
| 22 | **关闭 UAC、SmartScreen、防火墙，开启 SMB1**（新增） | 都在降低安全性；SMB1 就是「永恒之蓝」（WannaCry）利用的协议 | 解释弹窗出现的原因；兼容老设备时给出更安全的办法 |
| 23 | **用 hosts 或防火墙屏蔽微软域名**（新增） | Defender 会报 HostsFileHijack；还会搞坏更新、激活和应用商店 | 隐私相关只改系统自带的官方开关 |
| 24 | **清空事件日志、删除卷影副本或还原点、用 bcdedit 改恢复设置**（新增） | 这些是勒索软件的典型动作，会触发杀软的行为检测；也会毁掉排查问题的证据 | 需要释放还原点占用的空间时，引导用户使用系统自带的磁盘清理 |
| 25 | **手动删除 WinSxS 或 `C:\Windows\Installer` 里的文件**（新增） | 网上流传的「清理大法」，删了之后无法更新系统、无法卸载软件 | 用 `DISM /StartComponentCleanup` |
| 26 | **把暂停更新延长到超过系统界面允许的天数**（新增） | 等于变相永久禁用更新 | 系统允许范围内的暂停 |
| 27 | **替用户关闭内存完整性 / VBS**（新增） | 这是安全功能。游戏玩家常要求，但只应由用户自己决定 | 解释利弊，打开对应的系统设置页，由用户自己改 |

### 5.2 暂不做（以后可重新评估）

| # | 暂不做的事 | 为什么现在不做 | 替代做法 | 什么时候再考虑 |
|---|---|---|---|---|
| 11 | **驱动下载库 / 一键装驱动** | ①要维护海量驱动，工作量是天文数字；②驱动分发涉及版权；③装错驱动可能蓝屏、开不了机；④驱动更新通道本身就是攻击目标，驱动人生 2018 年被劫持植入过挖矿木马 | Windows 更新的可选驱动、品牌官网链接（按型号直达）、驱动备份与恢复 | 基本不会做 |
| 12 | **内置 PE / 自己做 PE 启动盘** | ①工作量大；②微 PE、Edgeless 等已经做得很好；③WinPE 组件的再分发有授权限制；④Rufus、Ventoy 都是 GPL-3.0，**许可证本身不是障碍**（我们选 GPL-3.0 就能合法打包；即使选 MIT，作为独立程序一起分发也只算「聚合」）。真正的问题是：打包后要跟着它们更新、要为它们的安全负责（Ventoy 2024 年曾被质疑仓库里有大量无法从源码复现的二进制文件），还会增加杀软误报 | 引导用户使用 Ventoy 或 Rufus 配合官方镜像，推荐可信的 PE | 1.0 之后看需求 |

| 15 | **「一键加速」「内存释放」「注册表清理」** | 效果可疑，甚至有害：释放内存会导致程序变卡，注册表清理微软明确不支持。这类功能是「管家」制造焦虑的套路 | 只做有实际效果的清理（磁盘空间）和启动项管理；硬件是瓶颈就直说 | 不做 |
| 16 | **在现有系统上强行升级 Win11，绕过硬件限制** | 属于不受支持的安装方式，以后可能收不到大版本更新，出问题难排查 | 自动应答生成器里提供「跳过硬件检查」选项，默认关闭，写明风险 | 视微软政策再评估 |
| 17 | **支持 Win7 / Win8** | ①技术栈不支持（WebView2 和 .NET 8 都已放弃 Win7）；②国内只占约 4%；③系统本身已停止支持多年，维护它们意义不大 | 在官网上建议 Win7 用户升级或重装 | 不做 |
| 18 | **AI 智能诊断** | 要联网和付 API 费用，和「不上报数据」的原则有冲突，还会增加成本 | 本地规则库诊断（症状 → 检测 → 修复）+「复制给 AI」（4.8） | 1.0 之后评估「用户自带 API Key、本地脱敏、逐次确认」的可选功能 |

| 20 | **Mac / Linux 版本** | 问题场景完全不同，会分散精力 | — | 不做 |
| 21 | **企业批量管理**（域、组策略、统一下发） | 目标用户不是企业；这方面有专业方案 | 预设套餐（4.5），满足小门店的需求 | 不做 |

### 6.2 核心设计：两层数据 + 引擎原语

v1.0 是「一个功能一个文件，撤销靠手写脚本」，有两个问题：

1. **「按症状修复」需要的是诊断树，而不是平铺的功能列表。** 「上不了网」要按顺序查网卡、IP、网关、外网、DNS、代理、系统时间，断在哪一环就修哪一环。
2. **手写撤销脚本很难写对。** 八成的修改只有几类：注册表值、服务启动类型、计划任务、启动项、电源设置、文件改名。WinUtil 的撤销写回的是预设的「默认值」，而不是这台电脑修改前的真实值——这一点不要学。

所以 v1.1 改成：

- **症状层**（`symptoms/`）：决定先查什么、再查什么，定位断在哪一环。
- **功能层**（`features/`）：一个个原子修复。
- **原语**：上面那几类常见修改由引擎原生实现。执行前自动记下原值（包括「原来不存在」和值的类型），撤销时原样写回。只有复杂的修复才写脚本，脚本要自己输出「修改前的值」交给引擎存档。

示例：

```yaml
# 症状层 symptoms/network.yaml：决定先查什么、定位断在哪一环
id: network
title: { zh-CN: 上不了网 }
keywords: [没网, 断网, wifi连不上, 网页打不开, 微信能用网页打不开]
checks:
  - network.adapter        # 网卡、飞行模式
  - network.dhcp           # 169.254.x.x → 路由器没分到地址
  - network.gateway        # 网关不通 → 路由器或网线
  - network.internet       # 外网不通 → 宽带问题，给运营商电话
  - network.dns
  - network.proxy-dead     # 代理指向 127.0.0.1:7890，但没有程序在监听
  - network.clock          # 系统时间错 → 所有 HTTPS 都失败
```

```yaml
# 功能层 features/network/proxy-off.yaml：原语类修复，不用写撤销
id: network.proxy-off
title: { zh-CN: 关掉已失效的系统代理 }
risk: safe                 # safe / caution / danger
scope: interactive-user    # 写到登录用户的 HKU\<SID>，不是提权后的账户
actions:
  - registry:
      key: HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings
      name: ProxyEnable
      type: dword
      value: 0
verify: network.proxy-dead # 修完自动复查
# 引擎执行前自动保存原值，撤销时原样写回
```

```yaml
# 功能层 features/disk/hibernation-reduce.yaml：带脚本的修复
id: disk.hibernation-reduce
title: { zh-CN: 缩小休眠文件（保留快速启动） }
description:
  zh-CN: 把 hiberfil.sys 缩小到内存的约 20%。之后不能再「休眠」，但快速启动和「睡眠」照常。
risk: caution
requires_admin: true
reboot: false
applies_to: { os: [win10, win11] }
detect: scripts/disk/hibernation-detect.ps1    # 输出 JSON：是否开启、类型、文件大小
run:    { command: powercfg, args: [/h, /type, reduced] }
undo:   scripts/disk/hibernation-restore.ps1   # 按快照里的原状态恢复
break:  scripts/disk/hibernation-break.ps1     # 测试用：制造「休眠文件很大」的状态
references:
  - https://learn.microsoft.com/windows-hardware/design/device-experiences/powercfg-command-line-options
```

**格式**：YAML 编写，构建时编译成 JSON，在 CI 里用 JSON Schema 校验。原因：Rust 常用的 `serde_yaml` 已于 2024 年归档停更；PowerShell 5.1 不能直接解析 YAML，命令行兜底模式读不了。键名用英文，中文放在值里，方便工具链和将来的多语言。

**功能文件的必填项**（贡献者照着填）：`id`、`title`、`description`、`risk`、`requires_admin`、`reboot`、`applies_to`（系统版本，以及家庭版 / 专业版等版本类型）、`detect`、`actions` 或 `run`、`verify`、`undo`（`auto` / 脚本 / `none` 加不可撤销的原因）、`break`（测试用的故障制造脚本）、`references`（优先引用微软文档）。

### 6.3 执行与权限

- **v0.1 采用「启动即请求管理员权限」**。这样实现最简单，也是同类工具的惯例（Dism++ 就是这样）。
- **用户设置写到 `HKU\<登录用户的 SID>`，而不是 HKCU**。用户用普通账户登录、再输入管理员密码运行时，注册表类的设置也不会写到管理员账户上——v1.0 里说的边界问题在 v0.1 就能解决。需要以用户身份做的事（例如重启资源管理器、按用户安装软件），用登录用户的身份启动。
- **前后端接口按「以后会拆成两个进程」来设计**：将来改成「普通权限界面 + 按需提权的辅助进程」时不用重写。
- **常驻 PowerShell 宿主进程**：每启动一次 powershell.exe 要 0.5–3 秒，装了 360 的老机械硬盘电脑更慢，30 项检测串行跑下来，30 秒远远不够。所以只启动一个宿主进程，通过标准输入输出收发 JSON；常用的读取（注册表、服务、WMI）直接用 Rust 实现。
- **长任务**：SFC、DISM 这类要显示进度、可以取消、有超时；体检里不跑它们。
- **启动前检查 WebView2**：用一个原生小启动器先检查，缺失就弹窗说明，并给出微软官方的安装链接，而不是直接闪退。
- 每次执行前都显示确认框：要改什么、风险等级、能否撤销。执行过程实时输出日志。
- 以管理员身份运行的窗口，收不到从资源管理器拖进来的文件（系统限制）。需要选文件的地方都提供「选择文件」按钮。

### 6.4 修改日志与撤销

- **自动快照**：原语执行前，引擎自动记下原值；脚本类修复自己输出修改前的值。
- **撤销前先核对**：当前值还是当初写进去的那个吗？被用户或别的软件改过，就先提示，不盲目覆盖。
- **「一键撤销」按倒序执行**：后改的先撤。
- **日志放在被修改的电脑上**：`%ProgramData%\<项目名>\journal\`，只有管理员能写。原因有两个：①便携版的日志如果放在 U 盘上，U 盘拔走就撤销不了；②日志是提权操作的输入，放在普通用户能写的地方，恶意程序就能篡改它，借「撤销」提权。
- **需要重启的修复**：记下待复查的项目，下次打开程序时自动复查，并告诉用户结果。
- **还原点只是最后一道保险**：它可能没开；Windows 默认 24 小时内只允许创建一个，程序需要检测并处理这种情况；创建要几十秒到几分钟；磁盘空间紧张时会被系统删掉——恰好就是「C 盘满了」的场景。所以主要靠修改日志撤销。

### 6.5 安全设计（新增）

它是一个以管理员身份跑在很多人电脑上的程序，本身就是高价值的攻击目标。

| 方面 | 做法 |
|---|---|
| 前后端边界 | 前端发给后端的只能是「功能 ID + 经过 Schema 校验的参数」，永远不能是命令字符串或脚本路径。Tauri 2 的权限配置只开放用得到的命令，不启用任意命令执行。导入的药方、预设套餐、软件清单也一样，只能引用已知的功能 ID |
| 不可信字符串 | 软件名、窗口标题、事件日志、文件名都可能是攻击者构造的。禁用 `v-html`，开启严格的 CSP，不加载任何远程内容。提权运行的 WebView 里出一个 XSS，就等于管理员权限的远程代码执行 |
| 脚本完整性 | 脚本嵌进 exe，或者每次执行前用 exe 内置的哈希清单校验。便携版尤其要注意：U 盘插过别人中毒的电脑，里面的脚本可能已经被改了 |
| 不开本地服务 | 不开本地 HTTP 服务，不注册会直接执行操作的 URL 协议。〔待补：厂商管家的漏洞教训〕 |
| 供应链 | 锁定依赖版本，安装时加 `--ignore-scripts`；用 pnpm 的 `minimumReleaseAge`（新版本发布几天后再用）；GitHub Actions 按 commit SHA 固定；用 cargo-deny 检查 Rust 依赖；开启 GitHub 的构建来源证明（artifact attestations）；发布要手动审批；所有账号开两步验证。2025 年 npm 的 chalk / debug 被投毒、Shai-Hulud 蠕虫、tj-actions/changed-files 被篡改，都是真实发生的事；CCleaner 2017 年更是出过带官方签名的安装包被植入后门 |
| 社区脚本 | 社区提交的脚本，就是会以管理员权限运行的代码。CI 规则：脚本禁止联网，禁止 `iex`、`DownloadString`、`-EncodedCommand`，禁止大段 base64 和混淆代码；用 PSScriptAnalyzer 做静态检查；脚本的改动必须经维护者审核 |
| 漏洞报告 | 写一份 SECURITY.md，给出私下报告漏洞的渠道 |

### 6.6 国内环境的技术要点（新增）

| 问题 | 做法 |
|---|---|
| 精简版、Ghost 版、LTSC 很常见 | WebView2、winget、应用商店、部分服务都可能被删掉，而最需要修的恰恰是这些电脑。启动前检查 WebView2；装软件前自检 winget；关键组件缺失时如实说明。懂哥的 U 盘版可以附带 WebView2 固定版运行时（放在签名包之外，见 6.9） |
| 家庭中文版 | 很多 Policies 注册表项只对企业版和教育版生效。每个设置项都要在家庭中文版上验证，功能文件里写明适用的版本类型 |
| 编码 | 系统命令按 GBK 输出，sfc 输出的是 UTF-16；PowerShell 5.1 读取不带 BOM 的 .ps1 时按 GBK 解码，里面的中文会乱码。规则：.ps1 一律存成带 BOM 的 UTF-8（或者脚本里不写中文）；脚本统一输出 JSON；**不解析命令输出的文字**（中英文系统、不同版本的措辞都不一样），改用返回码、WMI / CIM、注册表、事件日志、CBS.log |
| 360、腾讯电脑管家的主动防御 | 修改注册表、服务时会被拦截，并弹窗询问用户。杀软测试不光看报不报毒，还要看拦不拦截；界面上提前告诉用户可能会出现的弹窗 |
| 杀软的行为检测 | 设计上就不碰：`-EncodedCommand`、下载后执行、`vssadmin delete shadows`、用 bcdedit 改恢复设置、`wevtutil cl`、关防火墙、IFEO、用 hosts 屏蔽微软域名、改 Defender 设置。这些都是勒索软件和木马的典型动作，写进 CI 的禁用清单 |

### 6.8 测试

| 类型 | 做法 |
|---|---|
| 数据校验 | CI 里用 JSON Schema 校验所有功能文件；检查每个功能都有 `detect`、`verify`、`undo`（或不可撤销的原因）和 `break` |
| 脚本单元测试 | 用 Pester 验证每个脚本。GitHub Actions 的 Windows 运行环境是服务器版，只用来跑单元测试和只读检测 |
| 虚拟机自动化 | Hyper-V 快照 + PowerShell Direct，每个修复项自动跑「制造故障 → 检测到 → 修复 → 复查通过 → 撤销 → 和快照对比」 |
| 测试矩阵 | Win10 22H2、Win11 最近两个版本；**家庭中文版和专业版都要有**；Win10 LTSC 2021、Win11 LTSC 2024；至少一台装了 360 |

### 6.9 构建、签名与发布

1. **自动构建**：GitHub Actions 在 Windows 环境上构建，产出安装包和便携版 zip，并生成构建来源证明。
2. **代码签名：申请 SignPath Foundation 的开源免费签名。** 它的条件要提前准备：
   - 项目必须**已经发布过**，所以第一个版本必然没有签名；
   - 证书上的发布者是「SignPath Foundation」，不是我们的项目名，官网要教用户认准这个名字；
   - 官网首页写明代码签名政策和隐私政策，列出团队成员及其角色；
   - 所有成员开两步验证；由 CI 从源码以可验证的方式构建；每次发布都要手动审批；
   - 不能包含专有组件（系统库除外），所以 WebView2 固定版运行时不能放进签名包；第三方二进制（如 smartctl）不能用它来签，要沿用原作者的签名或单独说明；
   - 收集任何数据都要写明并可以关闭（检查更新也按这个标准处理）；修改系统前要提示；要提供卸载。
   - 另外，2024 年起连 EV 证书都不再能立即获得 SmartScreen 信誉，签名之后仍要靠下载量慢慢积累。**签名生效之前只发给种子用户，不公开推广**，否则就等于在教小白点「仍要运行」。
3. **发布渠道**：
   - **国内主渠道：对象存储 + CDN**（阿里云 OSS / 腾讯云 COS），挂在自己的备案域名下，作为唯一官方下载地址。按量付费：1 万次下载 × 10MB ≈ 100GB，每月几十元。
   - GitHub Releases：面向海外和开发者。
   - Gitee 同步镜像：公开仓库要审核，发行版附件也有限制，只作补充。
   - 每个版本附 SHA256 校验值；同时上架 winget 和 Scoop。
4. **官网**：用 VitePress 做静态站，**托管在已备案的 miao.club 子域名 + CDN**。GitHub Pages 长期屏蔽百度爬虫，放在那里百度基本收录不到，而小白主要用百度搜；GitHub Pages 只做海外镜像。
5. **误报与白名单**：每个版本发布前提交——微软（以「软件开发者」身份向 WDSI 提交）、360 开放平台的软件认证、腾讯电脑管家的误报申诉、火绒的误报反馈。
6. **检查更新**：只请求一个静态 JSON（放在自己的 CDN 或 GitHub 上），不带任何标识；在隐私政策里写明，并提供关闭开关。

### 6.10 许可证

- **代码：GPL-3.0**。它能要求改版公开源码，但**挡不住下载站把程序包进「高速下载器」再分发**——这要靠商标（见第九节）。
- **知识库：CC BY-SA 4.0**。错误码解释、症状对照、软件清单、弹窗知识库单独授权，方便别的网站和工具复用。翻译微软文档要署名（大多是 CC BY 4.0）；设备名称可以用 pci.ids（BSD-3 / GPL-2.0+ 双许可）。
- **贡献**：用 DCO（提交时签 Signed-off-by），不搞 CLA。
- **可以参考和复用的项目**：WinUtil、Win11Debloat、Sophia Script、unattend-generator、PowerToys、CrystalDiskInfo（MIT）；BCUninstaller（Apache-2.0）。保留原版权声明即可。
- **更正 v1.0 的两处说法**：
  - privacy.sexy 是 AGPL-3.0。GPL-3.0 第 13 条明确允许和 AGPL-3.0 的代码合并，桌面程序基本碰不到 AGPL 的网络条款；只有选 MIT 时才是问题。
  - Rufus、Ventoy 都是 GPL-3.0，打包不是许可证问题（见 5.2 节第 12 条）。
- **仍然不能复制代码的项目**：tiny11builder（没有许可证）、Winhance（非标准许可）。

## 八、里程碑与排期

按一个人业余时间开发估算（每周约 10–15 小时）。有帮手可以压缩。

**工作量粗估**（按第一次做 Tauri 项目、包含虚拟机测试来算）：底座 60–80 小时；6 个 P0 症状 120–150 小时（每个症状都包含好几个检测点，光「上不了网」就有六七个）；常用功能加官网和 10 篇教程 120–150 小时；重装助手 80–100 小时；签名、便携版和文档约 40 小时。合计约 450–550 小时，而 22 周 × 每周 10–15 小时只有 220–330 小时，差了一倍左右。所以 v1.1 砍了范围、调了顺序。Win10 的 ESU 延期到 2027 年 10 月，重装助手晚一点做也赶得上。

| 阶段 | 周期 | 交付内容 | 验收标准 |
|---|---|---|---|
| **M0 准备** | 第 1–3 周 | 需求验证（用百度指数给症状排序；整理百度知道、知乎、微软问答里的高频问题；访谈 5 位懂哥）；定名、查商标并提交注册；注册域名和各平台账号；许可证、README；数据模型、原语清单、JSON Schema；**行走骨架**：用一个最简单的功能，跑通「检测 → 确认 → 快照 → 执行 → 复查 → 日志 → 撤销」；CI 能出包；虚拟机环境 | 骨架在 Win10、Win11 家庭版虚拟机上跑通；Schema 评审通过 |
| **v0.0 只读体检版** | 第 4–6 周 | 体检、诊断报告、硬件信息与升级建议、硬盘和电池健康、Win11 升级检测、BitLocker 提醒。全部只读，不改系统 | 在测试矩阵上跑通；Defender、火绒不报毒；正常发布但不公开推广，随后申请 SignPath |
| **v0.1 修复版** | 第 7–13 周 | 修改日志与撤销、还原点、修完复查、症状搜索；4 个症状：上不了网（链路图）、C 盘满了、开机慢、打印机与共享 | 每个修复项都能自动通过「制造故障 → 修复 → 复查 → 撤销 → 对比」；10 位种子用户试用 |
| **v0.2 常用版** | 第 14–19 周 | 常用功能（4.4）、反向修复（4.3）、报告 + 药方和预设套餐（4.5）、其余症状、重装前备份；官网和前 10 篇教程 | 50 款常用软件能一键装好；设置项全部可撤销，并在家庭版上验证过 |
| **v1.0** | 第 20–24 周 | 签名生效后公开推广；便携版；完整文档；贡献指南；issue 模板；国内杀软白名单；问题修复 | 签名生效；新用户不看文档也能完成 3 个常见修复 |
| **1.x** | 之后 | 重装助手全流程（含个性化装机说明、自动应答）、验机、AI 相关 | 在虚拟机里完整走一遍「备份 → 重装 → 恢复」 |

**关键路径**：数据模型与 Schema（M0）→ 原语执行器、修改日志和撤销（v0.1 前半段）。这两块决定了后续开发速度，必须先做扎实。

## 九、社区与运营

- **贡献方式**：

  - 懂哥：V2EX、少数派、吾爱破解（软件区）、IT 之家、小众软件、异次元软件世界、远景论坛；卡饭论坛是杀软爱好者的社区，也适合拿来做误报测试。

  - 越来越多的人直接问豆包、DeepSeek、元宝。教程写得结构清楚、步骤完整，更容易被 AI 引用。
  - 在你的博客（blog.miao.club）写开发日志。
- **信任建设**：
  - 每个版本都公开 VirusTotal 扫描结果；
  - 写一篇「我们不做什么」公开声明，内容来自本计划书第五节；

  - 教用户认准唯一官方下载地址，以及 UAC 弹窗里的发布者名称。
- **可持续**：赞助入口只放在官网和「关于」页，不在程序里弹窗。

## 十三、待拍板的事项（附建议）

1. **项目名**。「电脑小药箱」只是暂定名，需要确定正式名和仓库名。
   建议：避开「360 系统急救箱」「腾讯电脑诊所」这类已有的叫法；先查商标（第 9、42 类）和百度搜索结果；准备一个好拼写的英文或拼音短名，用作仓库名和 exe 文件名。「药箱」这个比喻可以贯穿整个界面：体检 → 诊断 → 开药（修复）→ 病历（修改日志）→ 药方（懂哥发来的方案），但别做成吓唬人的医疗风格。
2. **许可证**。建议：代码 GPL-3.0 + 知识库 CC BY-SA 4.0 + DCO + 商标使用政策（见 6.10）。
3. **管理员权限策略**。建议：接受「启动即请求管理员」，同时做到用户设置写 `HKU\<SID>`、前后端接口按拆进程来设计（见 6.3）。
4. **官网放哪里**。建议：以国内为主（miao.club 子域名 + CDN），GitHub Pages 做海外镜像（见 6.9）。
5. **是否需要合作者**。建议：需要。最适合分出去的是「内容」（教程、视频、弹窗知识库、品牌按键表）和「测试」（虚拟机矩阵、国内杀软兼容），这两块都不需要深入代码。
